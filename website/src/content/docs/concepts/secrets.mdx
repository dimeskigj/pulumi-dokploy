---
title: Secrets
description: Keep Dokploy credentials and secret values protected in Pulumi.
---

Secret inputs include the provider API key, database passwords, environment values, application build arguments, application build secrets, and nested Docker credentials. Mark them as Pulumi secrets:

```bash
pulumi config set --secret dokploy:apiKey "$DOKPLOY_API_KEY"
pulumi config set --secret app:databasePassword "use-a-secret-manager-value"
```

Secret outputs derived from provider state remain secret as well. Do not commit credentials or print them in diagnostics. Never log API keys, database passwords, environment values, build secrets, or registry passwords. Use secret configuration or secret outputs when passing values between resources.

Imported resources can have write-only secret fields that Dokploy cannot return. Restore those inputs in configuration before a future update; see the [imports guide](../../guides/imports/).

Notification credentials (`webhookUrl`, Telegram `botToken`, SMTP `password`,
Resend `apiKey`, Gotify `appToken`, Ntfy `accessToken`, Pushover `userKey` and
`apiToken`) and Custom `endpoint`/`headers` are secret. Gotify/Ntfy `serverUrl`
is also marked secret because URLs may embed credentials. For example, use
`pulumi config set --secret notificationWebhookUrl <webhook-url>` and
`config.requireSecret("notificationWebhookUrl")`, not a literal webhook in source.
Import may not recover omitted required credentials: an empty secret in state is
not usable for an update. See the [Notifications guide](../../guides/notifications/).
