title: GitHub integrations
description: Import and manage an existing Dokploy GitHub App integration.

**Beta**

`GitHubIntegration` manages the Dokploy configuration for an existing GitHub App
integration. It does not create a GitHub App, authorize it, or guarantee a
working connection. Set up the App in GitHub and complete authorization in
Dokploy before importing it. The Dokploy API key must belong to a user allowed
to read and manage Git-provider integrations.

## Setup and import

In GitHub, create/configure the App and permissions required by your
organization. In Dokploy, add the GitHub provider integration and complete its
authorization flow. Then import its Dokploy GitHub relation ID (`githubId`),
not the GitHub App ID, installation ID, or parent `gitProviderId`:

```sh
pulumi import dokploy:index:GitHubIntegration integration <github-relation-id>
```

For an explicitly opted-in Pulumi program, use the import options form below
with reserved placeholders replaced by your stack-specific values. It is not
part of the canonical all-resources example and will not create the integration:

```ts
const integration = new dokploy.GitHubIntegration("integration", {
  name: "production-github",
  githubAppName: "existing-app-name",
}, {
  import: "<github-relation-id>",
});
```

After import, Pulumi manages the Dokploy `name` and `githubAppName` settings.
Changing the latter updates only Dokploy's setting; it does not rename or
reconfigure the GitHub-side App. If an imported record has no app-name value,
set a nonempty `githubAppName` before attempting an update. The provider's real
Create operation always reports that setup and authorization must happen in
Dokploy and the existing integration must be imported; it makes no API request.

## Destroy behavior

Destroy removes the Dokploy integration record only. It does not delete the
GitHub App, uninstall it, revoke upstream authorization, or delete workloads.
Review unmanaged workloads (Application and Compose references) before destroy: they are
not tracked as dependencies and may stop working when the integration record
is removed. See the [GitHubIntegration reference](../../reference/github-integration/)
and [Applications guide](../applications/).
