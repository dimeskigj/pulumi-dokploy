---
title: Applications
description: Create and update Dokploy applications from Docker, Git, or GitLab sources.
---

Create a Docker application by selecting the `docker` source variant. A Project owns the default production Environment; use an explicit Environment when this application belongs in staging or another non-production target.

```typescript
const app = new dokploy.Application("web", {
  name: "web",
  environmentId: environment.environmentId,
  source: { type: "docker", docker: { image: "nginx:latest" } },
});
```

For a public Git repository, select `type: "git"` and provide the URL, branch, and build settings:

```typescript
const gitApp = new dokploy.Application("git-web", {
  name: "git-web",
  environmentId: environment.environmentId,
  source: {
    type: "git",
    git: { url: "https://github.com/example/web.git", branch: "main", build: { type: "nixpacks" } },
  },
});
```

For an existing GitLab integration, select `type: "gitlab"` and pass its integration and repository metadata. Supply an external integration ID or the `gitlabId` output of a managed `GitLabIntegration`:

```typescript
const gitlabApp = new dokploy.Application("gitlab-web", {
  name: "gitlab-web",
  environmentId: environment.environmentId,
  source: {
    type: "gitlab",
    gitlab: {
      integrationId: managedGitlabIntegration.gitlabId, projectId: 42, owner: "example",
      namespace: "platform", repository: "web", branch: "main", build: { type: "nixpacks" },
    },
  },
});
```

Creates and updates fetch the selected source and wait for deployment completion. A source discriminator change replaces the Application; `environmentId` and `serverId` are also replacement-only. Other metadata and source settings update through the normal Pulumi diff. The Project/Environment is a dependency; GitLab integrations can be managed or external, and SSH keys can be managed by this provider. See [sources](../../concepts/sources/) and the [Application reference](../../reference/application/).

Managed integration configuration does not perform OAuth. Authorize it in the
Dokploy UI before deploying a GitLab-backed Application; keep Docker or generic
Git active until that second stage. See the [GitLab integrations guide](../gitlab-integrations/).

For a generic Git source, supply an existing `SSHKey` through its `sshKeyId`.
Applications may reference a managed `Registry` with `registryId` for deployment
images and `buildRegistryId` for build images. Registry credentials are secret
inputs and the provider tests the registry before creating or updating it.
