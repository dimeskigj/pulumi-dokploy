---
title: Backups
description: Schedule database and volume backups to an S3-compatible destination.
---

Backups need a `Destination` first: an S3-compatible storage target that both `Backup` and `VolumeBackup` write to.

```typescript
const destination = new dokploy.Destination("backups", {
  name: "backups",
  accessKey: config.requireSecret("destinationAccessKey"),
  secretAccessKey: config.requireSecret("destinationSecretAccessKey"),
  bucket: "app-backups",
  region: "us-east-1",
  endpoint: "https://s3.us-east-1.amazonaws.com",
});
```

`provider` defaults to `"s3"`, the only backend Dokploy currently supports.

## Database backups

A `Backup` schedules dumps of a Postgres, MySQL, MariaDB, or MongoDB instance. Set exactly one of `postgresId`, `mysqlId`, `mariadbId`, or `mongoId`; Dokploy has no equivalent for Redis.

```typescript
const dbBackup = new dokploy.Backup("app-db-backup", {
  schedule: "0 0 * * *",
  prefix: "app-db-",
  destinationId: destination.destinationId,
  database: "app",
  postgresId: database.postgresId,
});
```

`database` is the database name inside the target instance to dump, not the Pulumi resource name. Changing the target (`postgresId`/`mysqlId`/`mariadbId`/`mongoId`) replaces the Backup; `schedule`, `prefix`, `destinationId`, `database`, `keepLatestCount`, and `enabled` update in place.

## Volume backups

A `VolumeBackup` schedules backups of a named Docker volume for an Application or Compose service. Set exactly one of `applicationId` or `composeId`; for Compose, also provide `serviceName`.

```typescript
const volumeBackup = new dokploy.VolumeBackup("app-data-backup", {
  name: "app-data-backup",
  volumeName: "app-data",
  prefix: "app-data-",
  destinationId: destination.destinationId,
  cronExpression: "0 0 * * *",
  applicationId: app.applicationId,
});
```

For a Compose service, use the alternate target instead of `applicationId`:

```typescript
const composeVolumeBackup = new dokploy.VolumeBackup("stack-data-backup", {
  name: "stack-data-backup",
  volumeName: "stack-data",
  prefix: "stack-data-",
  destinationId: destination.destinationId,
  cronExpression: "0 0 * * *",
  composeId: stack.composeId,
  serviceName: "web",
});
```

Changing the Application/Compose target or `serviceName` replaces the VolumeBackup; `volumeName`, `prefix`, `destinationId`, `cronExpression`, `keepLatestCount`, `enabled`, and `turnOff` update in place.

`Destination.secretAccessKey` is a write-only secret input: it is not returned during refresh and may need to be restored after import. Check the exact fields in the [Destination reference](../../reference/destination/), [Backup reference](../../reference/backup/), and [VolumeBackup reference](../../reference/volume-backup/) before applying.
